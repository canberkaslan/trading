The bar cannot show a short. Weight is gross market value, absolute on both the numerator and the denominator, so a short leg paints exactly like a long one of the same size and the legend gives it the same positive percentage. On a long-only paper book — what this dashboard runs today — the distinction never surfaces. It is recorded here because the component has no way to express it: there is no second colour, no sign, no hatch, and the four segments are already spoken for by rank. Any future short book needs a decision at this level, not a patch in render().

Track width, gaps and shrink

Desktop track — .cols right column, 330px
330 − 2 border − 44 padding = 284px track 4 segments → 3 gaps → 6px spent on gaps ink available to the segments: 278px = 97.9%
The percentages are never quite the percentages. The children's widths already sum to 100% of the track, and then gap:2px asks for 6px more. Nothing is clipped: <i> is empty, so its automatic minimum size is 0 and the default flex-shrink:1 takes the 6px back out of every segment in proportion to its width. Ratios between segments survive exactly — the bar stays honest about relative size — but each segment renders at 97.9% of its stated share of the visible track: 34.2% draws as 33.5%, 27.9% as 27.3%. The error is a property of the track width, not of the data, so it shrinks as the card widens. overflow:hidden is doing only one job here, rounding the outer corners against border-radius:5px.
284px track → each segment −2.1% relative (34.2 reads 33.5) 726px track → −0.8% relative (34.2 reads 33.9) 1 segment, 0 gaps → the empty book is the only exact case

It is not a mount animation
Every refresh replays it. render() rewrites #alloc.innerHTML with width:0% on all four segments and lets the next frame set the real widths, so the bar collapses to nothing and grows back once a minute on the 60s poll — and again on every language toggle and period change. The chart guards against exactly this with a DRAWN flag; the allocation bar has no equivalent. The card animation is right the first time and wrong every time after.
boot() → setInterval(refresh, 60000) → render() → innerHTML → rAF no DRAWN-style guard on .alloc — the reset is unconditional prefers-reduced-motion hides it: the bar simply snaps to width

Why the remainder is grey and not a fourth blue. The three blues are one ordered scale: they encode rank, and reading them left-to-right tells you the book is getting less concentrated. "Diğer" is not rank 4 — it is an aggregate of an unknown number of names, and its width says nothing about any single position. Giving it #a7c4f2's successor would invite the eye to read it as the fourth-largest holding and would put the palette's lightest, highest-contrast step on the least informative segment. #3a414c sits above the --s3 #1c2027 the P&L bar uses for its track and well below --ink3 #828b9a, so it reads as ground rather than as data.
#3a414c is not --s3 (#1c2027) and not --bench (#767f8c) — it is a fourth, undeclared neutral used only here

Number formatting in the legend

NVDA 34.2% MSFT 22.8% Other 27.9%
LANG='tr' (default) → '%' + v.toFixed(1), t('other_word') = 'Diğer' LANG='en' → v.toFixed(1) + '%', t('other_word') = 'Other'
The decimal separator is not localised. pctNum() moves the percent sign to the Turkish side but keeps toFixed(1)'s dot, so Turkish renders %34.2 where the locale wants %34,2 — even though the file already carries a LOCALE() helper that returns 'tr-TR' and is used for the header timestamp and the decision dates. The legend is the only place in the risk card where this shows; the .kv rows use toFixed() with a bare '%' suffix in both languages, so "En büyük ağırlık" reads 14.2% in Turkish while the legend beside it reads %34.2. Two percent conventions, one card.
legend: share of gross · kv "En büyük ağırlık": share of equity same book, different denominators — 34.2% of gross = 28.0% of equity at 82% gross exposure (concentration.py: top_weight_pct is "largest single name as % of equity")
