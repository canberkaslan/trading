verdict
"GO" · "NO-GO" · "TOO EARLY" — the API's EvalResult.verdict is one of exactly these three (routes/eval.py via scripts/eval_report.py::_verdict)
cls
wait is the else branch, so any future verdict value would land on amber with the GO-shaped label
days_required
MIN_TRADING_DAYS = 10 (scripts/eval_report.py L38) — that is the /10 in the counter
className
assigned, not toggled: 'live '+cls replaces the element's whole class list on every render
The pulse is not disabled under reduced motion. The @media(prefers-reduced-motion:reduce) block at L36–40 only kills .rise, .tape-in and *{transition} — .live .d::after keeps animating. The JS flag RM (L325) likewise gates only the number tween (L436) and the chart draw-in (L678). The pulse in this card is therefore live in both settings, exactly as in the product.
Token gap: go and nogo use the --pos-dim / --neg-dim tokens for their background; wait hardcodes rgba(226,185,59,.12) because no --warn-dim token exists. Same value shape, one is just not tokenised.
No live region: the shipped markup is a plain <span class="live wait" id="verdict"> with no role, no aria-live and no label on the decorative dot. The verdict changes silently on every refresh, so assistive tech is never told that GO became NO-GO.
