Content rule & what the code actually does
  • The tape should carry the INTRADAY change, not position return. A tape that disagrees with the hero number is worse than no tape: on a day the book is down, every name can still read up double digits because each one is measured from its own entry, not from the previous close.
  • The shipped line reads position P&L, and always has. dashboard.html:466 renders pct(p.unrealized_pnl_pct*100,1) — unrealized return since entry, straight off Alpaca's unrealized_plpc (api/routes/portfolio.py:129). Nothing in the snapshot schema carries a per-position daily change yet, so the rule above is not implemented; the tape has shipped this way since it was introduced. Documented as-is rather than drawn as if it were fixed.
  • Order is whatever the snapshot returns — snap.positions.map(...) does not sort. Only the positions table below sorts (L494, by unrealized_pnl desc).
  • Duration is fixed at 36s regardless of item count, so a 3-name book crawls and a 12-name book races. The tape's speed is a function of how many positions are open, which is not a signal anyone wants encoded in motion.
  • The translateX(-50%) loop is off by half a gap (17px): the doubled list has 2N−1 gaps, so half its width is N·w + N·g − 17px while one true period is N·w + N·g. The seam jumps 17px once per cycle.
  • With a single position the doubled list is two items and is narrower than the viewport, so the −50% translate slides the pair leftward across empty space and snaps back — the loop never reads as continuous at all.
  • refresh() re-renders every 60s (L410) but the tape animation is 36s, and innerHTML is reassigned on the still-animating #tapein. Item widths change with the price digits, so the −50% target moves mid-cycle.
  • .tape-in has padding:8px 0 and no horizontal padding, so items start flush at x:0 while .wrap and .top-in both sit inside a 20px gutter.
  • The whole bar lives inside #app, which is display:none until the access token validates (L224, L406–414) — so before auth the tape has no layout at all, which is a separate condition from [hidden].
  • There is no mobile counterpart. Nothing in mobile/app renders a tape or any marquee; the RN app shows each position as a tappable card on the Portfolio tab that routes into the Ask tab, and its palette is a different green/red pair (up #22c55e / down #ef4444, src/theme/colors.ts) from the web's --pos #00d17a / --neg #ff5d6c.
