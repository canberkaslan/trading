Three screens, three answers, for the same five ratings. The API type is Rating = 'Buy' | 'Overweight' | 'Hold' | 'Underweight' | 'Sell'. Web collapses it into three buckets, so Buy and Overweight are pixel-identical and Underweight and Sell are pixel-identical — two of the five ratings are unreadable from colour alone. Mobile keeps all five distinct but abandons the chip entirely, and defines the map twice (agents.tsx and ask.tsx hold byte-identical copies) with no shared token for two of them (#86efac, #fda4af are inline literals, absent from theme/colors.ts). trade/[ticker].tsx then drops the colour coding altogether and renders the rating as plain white 24px text. The greens and reds also differ per platform: web #00d17a / #ff5d6c vs mobile #22c55e / #ef4444. Nothing in either codebase reconciles them.

States that do not exist in the source: no hover, focus, pressed, disabled, loading or selected variant is defined for .rchip — the only motion is the parent .dec row's translateX, and neither element is focusable or clickable, so the global :focus-visible outline never reaches them. On mobile the rating text sits inside a Pressable in both agents.tsx and ask.tsx, but each passes a static style object rather than a ({pressed}) => … callback, so there is no pressed state either. There is no fallback branch for an unknown rating string: web's ternary falls through to 's' and renders it as Sell red, while mobile's Record lookup yields undefined and the text falls back to the RN default colour on a #171717 card.
