Three icons, four situations — the two null columns are the same pend() and differ only in what the detail line carries. Not-yet-evaluable is never a hover, press or loading state: it is the server saying passed: null, which happens when sc.days < 10 (all three metric gates — sharpe, max_drawdown, beats_spy — pend at once, and gate 1 shows bad() because its own passed = have_days = false) or when sc.spy_return is None. There is no hover, focus, pressed, disabled or skeleton state in the source — the strip has no :hover rule (unlike .chip), is not focusable, and render() writes the whole grid in one innerHTML pass. There is also no empty state: the web does ev.gates.map(...) unguarded, while mobile gates the same list behind evalData.gates?.length.

Wording rule — the detail line states the requirement, never a claim

Load-bearing. Comment lives at eval_report.py L322–323.

The detail line is the only place a number and its threshold sit together, and it is read at a glance next to a red cross. An earlier version rendered the comparison itself, so a failing Sharpe printed a false proposition on the face of the card. The fix is to print the measurement, then the requirement in parentheses — the sentence stays true no matter which icon is beside it.

was — asserts something false
-0.44 > 1.0
is — states the requirement
-0.44 (need > 1.0)
tr — only the phrase is swapped
-0.44 (gereken > 1.0)

Localisation is a literal two-token replace in render(): String(g.detail).replace('need >',t('need_gt')).replace('need <',t('need_lt')) — the number, the parentheses and the operator are the server's. Gate names go the other way: translated from a stable g_<key> key, falling back to the server's English g.name so an older deployment still renders a named gate.

What the tile cannot tell you

  • Web and mobile do not share this component. settings.tsx GateRow draws the same three states as text glyphs — ○ ✓ ✗ at 13px / weight 800 in a 16px column — in a different palette (up #22c55e, down #ef4444, textMuted #949494) in a full-width row, and renders the raw English g.name with no g_<key> lookup, inside an otherwise Turkish screen.
  • The detail line's minus is ASCII. build_gates() emits -0.44 (U+002D) and the dashboard passes it through untouched, while every other number on the page goes through sgn() and gets a typographic − (U+2212). The Sharpe gate and the Sharpe chip disagree on the same value.
  • Turkish percent formatting is bypassed. The page has pctNum() for the %2.9 / 2.9% split, but gate details are server strings — so the max-drawdown tile reads 2.9% (gereken < 15%) while the chip's threshold beside it reads eşik %15. The chip's own value (ev.max_dd_pct.toFixed(1)+'%') skips pctNum() too, so the same page shows both orders.
  • "benchmark off" has no i18n key. It stays English in the Turkish UI, and it is the only detail string that is prose rather than a measurement.
  • Contrast — fixed, but unguarded on web. --ink3 is now #828b9a: 5.18:1 on --s2, 5.45:1 on --s1, 5.73:1 on --bg, so the 11px detail line clears WCAG AA. The previous #5d6673 was 3.06:1 on --s2 and failed. Mobile made the same move (#666 → #949494) and pinned it with utils/contrast.test.ts; the web dashboard still has no equivalent guard, so nothing stops the token drifting back.
  • Gate 1 fails rather than pends below day 10. passed = have_days, so while the other three sit at null the trading-days tile shows a red cross — a strip that is mostly grey with one red mark is the normal pre-evaluation frame, not an error.
  • The strip and the verdict chip can disagree. The Sharpe chip turns green at ev.sharpe >= ev.gate_sharpe; the gate passes only at sc.sharpe > GATE_SHARPE. At exactly 1.00 the chip is green and the gate is red.
  • The header and the first tile punctuate the same ratio differently. #gdays is built as ev.days+' / '+ev.days_required → 20 / 10 gün, while the trading-days detail is f"{sc.days}/{MIN_TRADING_DAYS}" → 20/10. Two spellings of one number, 200px apart.
