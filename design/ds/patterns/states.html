The skeleton never renders

.sk is markup inside #app, and #app{display:none} until boot() has already awaited refresh(true) → render() → drawChart(), which overwrites #chart.innerHTML. Period-tab switches don't reinstate it either. So the shimmer above is real CSS on an unreachable node: during the first fetch the user sees a blank page, not a skeleton.

No other block has a loading treatment. #chips, #gates, #positions, #alloc, #risk and #decisions are empty <div>s until the first render() fills them. The skeleton is also not exempted by the prefers-reduced-motion block (L36–40), which silences .rise, .tape-in and all transitions but neither sh nor rot.

The red "backend offline" strip cannot currently fire

hardOffline = isError && failureCount >= 2 (L36), but useReadiness is declared retry:false with a 30s refetchInterval (hooks.ts L203–209). TanStack Query resets fetchFailureCount to 0 at the start of every fetch, so with retries off the observed failureCount alternates 0 → 1 → 0 → 1 and never reaches 2. In practice a permanently unreachable backend stays on the amber '● bağlantı yeniden deneniyor…' line forever. The specimen above documents the intended state, not an observed one.

Six combinations from five statusText branches × three mode chips. Geometry is identical in all of them: paddingHorizontal 16 · paddingBottom 6 · paddingTop = insets.top (10px stand-in here), row gap 10 · minHeight 24, chip radius 6 · 8/3 padding, text 11px / 800 / +0.5 tracking for the chip and 11px / 600 for the status. The strip renders from the first frame so the header height never jumps. The bell stays 24×24 inside that strip and buys its 44pt target with hitSlop 10 rather than padding. What the states say about each other

  • Web translates its states; mobile has i18n but does not use it here. Every web string on this card comes from I18N.tr / I18N.en and swaps live. Mobile ships a real bundle (src/i18n/tr.json + en.json, picked from the device locale with fallbackLng:'en') — and not one loading, empty or error string on this card is in it. They are all hardcoded literals, mostly Turkish, with portfolio's 'Loading…' and agents' 'Decisions' / 'Refreshing…' in English directly above Turkish ones.
  • Three font sizes for one word. 'Yükleniyor…' renders at 12px (agents, orders), 13px (notifications) and — as 'Loading…' — at RN's default 14px (portfolio, whose muted style declares no fontSize at all). Settings says the same thing twice more in its own words, at 13px and 12px.
  • Red means two things on mobile. colors.down #ef4444 is both "a position is losing money" and "the backend is unreachable", and on the charts tab it is also the empty state ('Veri yok'), which is not an error.
  • Only the banner tries to escalate, and its second stage is dead. StatusBanner is the one place with a two-stage failure model (retrying → offline), but retry:false keeps failureCount at 1, so the red stage never arrives. Web's #err is identical on the 1st and 40th consecutive failure, and mobile's ErrorState fires on the first.
  • Empty is quiet on mobile, silent on web — and inconsistent on both. Mobile has seven written empty states in four different shapes plus one that renders nothing; web has one, for the chart, and lets an empty positions table and an empty decisions card just render as nothing.
  • Two disclosure philosophies for the same failure. Web prints the raw Error.message inline in the sentence for every user; mobile prints String(error) only where a caller passes detail (portfolio), demoted to 11px muted and clamped to two lines.
  • Reduced motion is half-wired on web. The media block at L36–40 kills .rise, the ticker and all transitions, but both infinite animations documented here — sh and rot — keep running.
