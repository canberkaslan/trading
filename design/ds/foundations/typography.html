Rule of thumb from the source: if the string was produced by usd(), usd2(), pct() or toFixed(), it is mono. The one string that breaks it is .flags — it prints pctNum() and toFixed() output in sans because the sentence around it dominates. Dates, the clock and the two counts come from toLocaleDateString / toLocaleTimeString / .length, so the rule never reaches them.

Notes from the source

things the specimens above cannot show
mobile has no mono mobile/app/src/theme/colors.ts defines no font tokens at all and no screen or component sets a fontFamily — every figure in the RN app renders in the system sans. The single numeric guard in the whole app is learn.tsx:169 progressText fontVariant:['tabular-nums']; the 36px hero value, the P&L column and EquityChart's equity endpoints have none.
two hero sizes Web .hero .big is 44px / 700 / ls −.02em / lh 1.05; mobile portfolio.tsx:541 heroValue is 36px / '700' with no tracking or line-height. Neither derives from a shared token — they were set independently.
weight 650 web-only The web declares 650 exactly ten times — h2, thead th, .chip .k, .chip .v, .ptabs button, .sym, .kv b, .rchip, .tk b, .lesson .lt — against eight uses of 700 (seven rules plus the inline #langbtn style). React Native fontWeight accepts only the hundreds, so mobile has 600 and 700 and nothing between — the two platforms cannot match here even in principle.
svg misses the rule The two chart end-labels (lines 668–669) set font-family="var(--mono)" as a presentation attribute but never get the .mono class, so they carry no font-variant-numeric. Harmless while the monospace stack resolves; it is one of the two numeric strings on the page not covered by the rule.
one ASCII minus Every other signed figure goes through sgn(), which emits U+2212. The drawdown chip is ev.max_dd_pct.toFixed(1)+'%' and max_dd is negative, so it prints a hyphen-minus at 16.5px next to chips whose minus is the real one. Same shape, different glyph width.
no italic on web The web dashboard ships zero font-style:italic and zero font-variant:small-caps. Emphasis is weight and colour only. (Mobile does use italic: the shared disclaimer is 11px italic on colors.textMuted #949494 on portfolio, learn, agents and ask — plus trade, approve and login — and settings.tsx evalReason is 11px italic on colors.warning.)
no responsive type There is no clamp(), no rem, and neither media query (max-width 900px / 760px) touches a font-size. The 44px hero is 44px on a phone.
