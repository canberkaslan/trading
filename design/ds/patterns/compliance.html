Compliance surface

Canonical text agent/tradingagents_us/compliance.py · web footer + .tag in dashboard.html · mobile styles.disclaimer across seven screens + StatusBanner

Every surface that renders a rating or a price target must carry the disclaimer, and it must be readable. The first half is an App Store requirement — guideline 5.2.1, financial trading — recorded as a release gate in mobile/RELEASE.md:61 (“Risk disclaimer visible on login + every trade screen (Apple 5.2.1)”) and again in its rejection-triage table at line 77. Until commit 1c6ff0e the gate was unmet: the four screens that actually render ratings and price targets had none — (tabs)/agents.tsx, (tabs)/ask.tsx, trade/[ticker].tsx, approve/[orderId].tsx. The same commit made the caveat travel with the data: every Decision the API serves now carries disclaimer and advice_status fields, so a client cannot receive a rating without the caveat already in hand. The second half arrived in 3cecc75, which raised both clients' muted greys off a WCAG AA failure — the disclaimer was the text those greys carried.

Resolved in 3cecc75: the compliance copy used to be the least legible text in the product, on both platforms. Mobile styled the disclaimer color: '#555' in seven StyleSheets — 2.66:1 on #0a0a0a, darker than the #666 that theme/colors.ts already records as rejected at 3.4:1. Because the literal never entered the palette, the token suite in utils/contrast.test.ts, which iterates over colors, never saw it. All seven now use colors.textMuted #949494 — 6.53:1 on #0a0a0a, 5.91:1 on #171717, 4.99:1 on #262626 — and a new case in that file walks every .tsx under app/ and src/components and fails on that class of literal. The web had drifted into the same bug independently: --ink3 was #5d6673, 3.39:1 on --bg, on the token behind the footer, eyebrow labels, table headers, timestamps and unselected period tabs. It is now #828b9a — 5.73:1 on --bg, 4.75:1 worst case on --s3 — guarded by agent/tests/test_dashboard_contrast.py, which parses :root and asserts every text token against every surface.

Four wordings for one obligation, and the canonical one is never shown. The API attaches DISCLAIMER to every decision precisely so that, in the words of schemas.py:61–62, “no client can render a rating or price target without the caveat already in hand” — but neither client reads the field. Grep for disclaimer in dashboard.html returns nothing, and mobile calls t('disclaimer.short') from its own bundle. So the shipped text is: the web footer (2 languages, mixes refresh cadence into the legal line), the i18n short form (2 languages), the login literal (English only), and the Python canonical (unused, plus an unused Turkish twin). The wire field is the only one that names not a solicitation and not personalized — the two clauses 5.2.1 actually turns on — and it is the one no user sees.

The two clients disagree about what “PAPER” means, and the gap runs the wrong way. Mobile reads trading_mode off the readiness poll and refuses to assert a mode it has not been told (MOD ?); the web tag is a static string that will keep reading PAPER after a live flip, on the surface that shows real equity. Mobile's own coverage is uneven too: StatusBanner is mounted in (tabs)/_layout.tsx only, so trade/[ticker].tsx, approve/[orderId].tsx and notifications.tsx render outside it — the approve screen, the one place a human commits an order, carries no mode chip. And the LIVE — GERÇEK PARA chip is #ffffff on colors.down #ef4444: 3.76:1 at 11px/800, the one chip in the app that must never be missed and the only text token pair in it that still fails AA. login.tsx's two placeholderTextColor="#666" are a second gap at 3.12:1 on #171717 — the new file-walking guard matches the literal color: '#666', not the placeholderTextColor prop.

States deliberately not shown, because the source has none: there is no acknowledged/dismissed state, no first-run consent modal, no expanded “full disclosure” sheet, no per-region variant, and no link target — on either platform the disclaimer is inert text. The web .tag has no LIVE sibling and no i18n key. The web footer has no compact/mobile breakpoint. advice_status has exactly one value in the codebase, "not_personalized_advice", and no branch reads it.
